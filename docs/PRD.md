## 1. 背景与目标

选品和内容选题需要回答："某个品类里，哪些商品卖得好、卖什么价、靠什么卖点？"人工浏览无法沉淀与回溯。本产品把"采集 → 存储 → 分析 → 决策"串成一条本机可运行的数据管道。

**v0.5 目标（一句话）**：在已跑通的采集与数据浏览之上，新增「分析」页——给定品类与批次，输出概览指标、价格/销量分布、店铺集中度、关键词与参数画像、卖点组合、爆款候选榜，并可选用 LLM 生成一份可直接用于选品/内容选题的解读。

### 非目标（本版不做）

- 跨批次趋势与命中率回测（需要连续数据积累，v0.6）
- 多平台（拼多多/1688）、多用户、云部署、自动交易
- SKU 逐个点选采价、全量详情采集

---

## 2. 用户与场景

**场景 A · 采集**：输入关键词与采样参数（默认 1 页 + 6 详情），页面实时进度；风控触发自动暂停，处理后续采。

**场景 B · 数据浏览**：按品类/批次查看一行一商品；默认只看已采详情；点击行看参数/SKU/历史；导出 CSV；删除无用品类/批次（二次确认）。

**场景 C · 批次分析（v0.5 核心）**：选品类+批次 → 查看概览指标、价格带/销量分布、店铺集中度、关键词、参数画像、卖点组合、爆款候选榜。

**场景 D · AI 解读（可选）**：点击"生成解读"，LLM 基于分析结果输出大盘、卖点聚类、价格供给、风险提醒、选品/内容建议五段结论。

**场景 E · 演示**：面试现场用演示数据展示采集 + 分析全链路。

## 3. 核心口径

| 指标 | 口径 | 说明 |
|---|---|---|
| 商品范围 | 天猫 tab 搜索结果第 1 页，按销量降序 | 结果受账号个性化影响，固定账号 |
| 详情对象 | 按页面顺序取 Top K（默认 6） | 可切"已售优先" |
| 到手价 | 详情"到手价/补贴到手价/券后价"；否则展示价−明示立减 | 详情缺失或与列表价偏离 >3 倍时回退列表价（口径：列表展示价） |
| 已售/加购 | 页面区间文本解析为下限（500+ → 500） | 非精确销量 |
| SKU / 主图 / 参数 | 只采 SKU 名称；首图 URL 一张；参数键值对 | 参数面板偶发跳过（拟人） |
| 分析样本 | 批次内全部候选；详情字段仅 Top6 商品有 | 分布类分析标注样本数 |

### 反风控约束（运行纪律）

- 详情是风险大头：每批 ≤6，每天 ≤1 批，同日不连跑；日详情 ≥10 时控制台提醒
- 节奏：列表 5–9s；详情 20–40s；每 2 个详情休息 90–180s；进详情前先浏览列表
- 触发验证/访问异常立即暂停，冷却 24–48h；账号与 IP 会被关联，换号只隔离主号风险
- **列表 DOM 解析不产生额外请求，候选存多少与风控无关**；旋钮优先级：详情次数 > 翻页深度 > 节奏 > 账号权重

## 5. 分析模块（v0.5 新增）

### 5.1 功能清单

| ID | 功能 | 优先级 | 验收标准 |
|---|---|---|---|
| F10 | 批次概览指标 | P0 | 商品数、详情数、价格中位数/四分位、已售中位数、TOP5 店铺销量占比正确；空批次给出引导 |
| F11 | 分布图表 | P0 | 价格带分布（各价位商品数与销量合计）、销量区间分布；柱条与数据一致，标注样本数 |
| F12 | 榜单 | P0 | 爆款候选 Top10（按已售下限）、店铺集中度表、关键词词频、参数画像 |
| F13 | 卖点组合聚类 | P0 | 基于价格带+容量+材质+功能词组合聚类，输出商品数、均价、均销量、示例标题；按商品数×均销量排序 |
| F14 | LLM 解读（可选） | P1 | 配置 API 后可一键生成五段解读；未配置时按钮给出配置指引；输出不得编造输入外数字 |

### 5.2 计算口径

- 价格：优先到手价，缺省用列表展示价；未知价商品不进入价格统计，但在计数中保留
- 销量：已售区间下限；无值不参与均值/分位
- 关键词：内置电商词表（保温/吸管/显温/冲锋衣/三合一/加绒/316 等）在标题中的命中次数
- 参数画像：覆盖率达到样本 40% 的参数键，展示 Top5 取值及次数
- 卖点组合：`价格带 · 容量段 · 材质 · 功能词(≤2)`；缺失维度自动省略；按 `商品数 × 均销量` 排序取 Top8

### 5.3 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/analysis/summary?task_id=&batch=` | 返回计数、价格/销量分布、店铺、关键词、参数、聚类、Top10 |
| GET | `/api/analysis/llm-status` | LLM 是否已配置 |
| POST | `/api/analysis/insights` | `{task_id, batch}` → LLM 五段解读文本 |

LLM 配置（环境变量，OpenAI 兼容）：`BK_LLM_BASE_URL`（默认 https://api.deepseek.com）、`BK_LLM_API_KEY`、`BK_LLM_MODEL`（默认 deepseek-chat）。

### 5.4 页面

新增「分析」Tab：品类/批次选择 → 指标卡 → 价格带与销量分布（自绘条形，无额外图表依赖）→ 店铺集中度 → 关键词 → 参数画像 → 卖点组合 → 爆款候选 Top10 → AI 解读卡片（未配置时显示配置指引）。

## 6. 数据模型（SQLite）

- `dim_task`：任务（关键词、页数、详情数、详情顺序、价格带）
- `product`：商品详情（标题、店铺、评分、好评率、SKU、参数、首图、链接）
- `fact_snapshot`：每批观测（rank、page_no、price_final、price_text、sold_text/sold_lb、cart_text/cart_lb、title/image_url/shop_name 列表级字段、is_detail）
- `batch_run`：批次状态与进度

## 7. 技术方案

```
baokuan-radar/
├─ bkr/                 # 采集核心 + 分析计算（analysis.py 纯函数）
├─ server/              # FastAPI；routes: collect/data/env/events/analysis
├─ web/                 # React + TS + AntD；panels: CollectPanel/DataPanel/AnalysisPanel
├─ 安装环境.bat / setup.bat, 启动.bat / start.bat
└─ data/radar.db, data/raw/
```

运行：`setup.bat` 一次安装；`start.bat` 日常启动；开发模式后端 uvicorn --reload + 前端 npm run dev。

| `config/settings.yaml` | 本机配置（推荐）：`profile` / `server.port` / `llm.base_url,api_key,model`；环境变量优先 |
| `BK_PROFILE` | 选择浏览器 profile（默认 `.browser-profile`，`alt` → `.browser-profile-alt`） |
| `BK_PORT` | 服务端口（默认 8765） |
| `BK_LLM_BASE_URL` / `BK_LLM_API_KEY` / `BK_LLM_MODEL` | OpenAI 兼容 LLM 配置（分析解读） |
